# 项目总结 —— 简历与面试复盘材料

---

## 1. 一句话项目介绍

基于 11.9 万条酒店预订数据，利用 Pandas 生态系统从取消行为、客户渠道、价格收入和入住行为四个维度展开 EDA，识别高取消风险因素并提出可落地的业务优化建议。

---

## 2. 技术栈

Python · Pandas · NumPy · Matplotlib · Seaborn · Jupyter Notebook · VS Code · Claude Code

---

## 3. 数据规模

- 119,390 条预订记录
- 32 个原始字段
- 覆盖约 3 年的酒店预订数据
- 涉及 2 类酒店（City Hotel / Resort Hotel）

---

## 4. 我在项目中完成的工作

1. 搭建项目结构（`src/` 模块化代码 + `notebooks/` 分析流程 + `outputs/` 图表输出）
2. 使用 Pandas 完成数据清洗：缺失值处理（5 个字段，4 种策略）、数据类型转换、异常值检查
3. 构造 9 个衍生分析字段，包括时间序列字段、客户分群标签和季节性标签
4. 编写 18 个可复用的分析函数（`src/analysis.py`），按业务主题组织，带清晰的 docs 说明
5. 完成 5 个分析 Notebook，覆盖取消行为、客户渠道、价格收入、入住时长与提前预订四大主题
6. 产出 23 张可视化图表，使用 Matplotlib + Seaborn，双轴图、分组柱状图、多面板对比图等
7. 从分析结果中提炼 8 条核心发现和 7 条业务建议
8. 撰写正式项目报告（`project_report.md`）和 GitHub README

## 5. 项目核心亮点

- **分析框架完整**：从数据清洗 → 特征工程 → 多维度 EDA → 可视化 → 业务建议，覆盖完整的数据分析工作流
- **代码模块化**：分析函数抽离到 `src/analysis.py`，Notebook 只负责调用与展示，可复用性强
- **业务思维贯穿**：每个分析步骤都对应具体的业务问题，结论有明确的业务含义和行动建议
- **异常值与边界条件处理**：对 ADR <= 0、total_guests == 0、lead_time 极端值等做了检查和标注
- **数据口径清晰**：收入分析明确区分未取消订单的实际收入与取消订单的潜在损失，避免概念混淆

## 7. 面试中可能被问到的问题与回答思路

### Q1：为什么要做这个项目？项目的业务价值是什么？

**回答思路**：酒店行业的预订取消率普遍偏高（本项目 37%），直接影响收入预测、库存管理和定价策略。与传统"被动接受取消"不同，通过数据分析可以识别高风险订单、高质量渠道和高价值客群，帮助运营团队有针对性地分配风控资源和营销预算。

### Q2：你是怎么处理缺失值的？为什么 company 不是简单填充？

**回答思路**：`company` 缺失率 94.3%，几乎全空，填充无意义——任何填充方式都会制造噪音。转为 `has_company` 布尔标识保留了"是否有公司关联"这一信号（虽然微弱），同时移除了无用的原始列。这体现了"先理解业务含义，再选择技术手段"的原则。

### Q3：你怎么看待 "Non Refund 订单取消率反而最高" 这个反直觉发现？

**回答思路**：这是典型的样本选择偏差（Selection Bias），不是政策无效。酒店通常对高风险客户主动设置不可退款条件，因此 Non Refund 订单的客户群体本身就是高风险群体。要评估不可退款政策的真实效果，需要用因果推断方法（如 PSM 倾向得分匹配）控制选择偏差后再比较。

### Q4：为什么重复客户占比这么低（3%），分析它们有意义吗？

**回答思路**：正因为占比极低、价值极高，分析才有意义——这恰恰是最大的增长机会。如果重复客户的取消率低 19 个百分点且 ADR 更高，将复购率从 3% 提升至 5-8% 带来的不仅是增量收入，还会拉低整体取消率这个核心运营指标。这是一个"小而确定"的改善方向。

### Q5：项目的局限性在哪里？如果有更多时间你会怎么做？

**回答思路**：当前项目是描述性分析（Descriptive Analytics），回答了"发生了什么"但没有回答"为什么发生"和"将发生什么"。下一步优先做两件事：①构建二分类取消预测模型（XGBoost / LightGBM），量化各特征的预测贡献；②用因果推断评估押金政策、最低入住晚数等干预措施的真实效果。此外，当前收入分析是粗略估算，实际环境中需要更精细的 revenue management 数据。

### Q6：如果业务方让你只推荐一个最有效的降低取消率的措施，你推荐什么？

**回答思路**：对提前 90 天以上的远期预订引入"不可退款低价 + 弹性可退款原价"的双轨定价。理由：提前预订天数是最强的取消预测信号（180 天+ 取消率近 70%），且这个信号在预订时就已知，不需要等待其他行为数据即可触发干预。双轨定价不是强制所有客户选择不可退款，而是用价格杠杆让客户自我选择，风险低的客户自然选低价。

### Q7：你在项目中遇到的最大挑战是什么？

**回答思路**：数据口径的清晰界定。例如收入分析中，取消订单的 `adr` 和 `total_nights` 也存在，但取消订单不产生实际收入——如果不能清楚地定义"实际收入"和"潜在损失"的区别，后续所有分析都会混乱。我的做法是：在分析函数中明确注释数据口径（只统计 is_canceled == 0），并单独用 `calculate_canceled_potential_revenue` 汇总取消订单的潜在损失，两者从不混用。
